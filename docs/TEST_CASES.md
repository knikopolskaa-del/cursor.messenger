# Тест-кейсы — Cursor Messenger (подробный реестр)

Полное ручное покрытие пользовательского функционала веб-приложения.  
Стек: React (Vite) + FastAPI + SQLite + Yandex Object Storage.

---

## Как поддерживать этот документ

**Обязательно при каждом новом или изменённом функционале:**

1. Добавить/обновить кейсы в соответствующем разделе.
2. Записать изменение в [Журнал изменений](#журнал-изменений).
3. Для P0/P1 — добавить Playwright в `e2e/*.spec.ts` (см. [Карта автотестов](#карта-автотестов)) и пометить **Автоматизация: ✅**.
4. Прогнать smoke по затронутым кейсам.

**Формат кейса:** ID · название · приоритет · тип · предусловия · шаги · ожидаемый результат · автоматизация.

**Приоритеты:** P0 — блокер релиза · P1 — важный сценарий · P2 — вторичный · P3 — косметика / заглушки.

## 1. Окружение и тестовые данные

### Запуск

```bash
npm run stack          # API :8001 + Vite :5173
npm run e2e:ensure-user
npm run test:e2e       # Playwright
```

### Учётные записи (seed / e2e)

| Email | Пароль | Роль | Назначение |
|-------|--------|------|------------|
| `test@example.com` | `1234` | employee | E2E, обычный пользователь |
| `maria@gmail.com` / seed admin | из `.env` | admin | Админ, создание каналов |
| `ivan@example.com` | `secret12` | employee | Собеседник в seed |
| `anna@example.com` | `secret12` | admin | Админ в seed |
| `alex.contractor@example.com` | `secret12` | guest | Гостевой доступ |

### Seed-объекты

- Каналы: `#общий` (`c_general`), `#дизайн` приватный (`c_design`), `#болталка` (`c_random`)
- Группа: «Команда запуска» (`g_launch`)
- DM: между admin/me и ivan, guest

### Query-параметры чата

| Параметр | Пример | Эффект |
|----------|--------|--------|
| `panel` | `?panel=info` | Правая панель 300px |
| `thread` | `?thread=m1` | Оверлей треда 400px |
| `focus` | `?focus=m2` | Прокрутка к сообщению, param удаляется |

Значения `panel`: `info`, `members`, `pins`, `docs`, `video`, `photo`, `links`, `audio`.

## 2. Авторизация и сессия

### TC-AUTH-001 — Пустая форма входа показывает ошибки валидации

- **Приоритет:** P0 · **Тип:** E2E · **Автоматизация:** ✅ `e2e/messenger.spec.ts`

**Предусловия:** пользователь не авторизован.

**Шаги:**
1. Открыть `/login`.
2. Нажать «Войти», не заполняя поля.

**Ожидаемый результат:**
- Отображаются «Введите e-mail» и «Введите пароль».
- URL остаётся `/login`.
- Запрос на `/auth/login` не уходит (или не приводит к успеху).

---

### TC-AUTH-002 — Успешный вход перенаправляет в приложение

- **Приоритет:** P0 · **Тип:** E2E · **Автоматизация:** ✅

**Предусловия:** `test@example.com` / `1234` существует.

**Шаги:**
1. Открыть `/login`.
2. Ввести e-mail и пароль.
3. Нажать «Войти».

**Ожидаемый результат:**
- Редирект на `/app` или `/app/c/...`.
- В `localStorage` ключ `messenger_access_token` не пуст.
- В сайдбаре видны имя пользователя и навигация.
